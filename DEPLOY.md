# 🚀 Деплой: Render + Supabase + webhook

Пошаговая инструкция: как перевести бота на хранение в Supabase и на webhook.

Как это устроено после перехода:

```
Telegram ──(HTTPS, webhook)──▶ Render: бот (просыпается от входящего запроса)
                                         │
                                         ▼
                               Supabase: PostgreSQL, схема readit
```

Что понадобится: сервис бота на Render, ваш проект Supabase и пароль от его
базы. Токен бота уже лежит в Render в переменной `BOT_TOKEN`.

---

## Шаг 1. Возьмите строку подключения в Supabase

1. Откройте проект в [Supabase](https://supabase.com/dashboard) и нажмите
   кнопку **Connect** вверху страницы.
2. Выберите **Session pooler** и формат **URI**.
   - Не берите *Direct connection*: она работает только по IPv6, а Render
     подключается по IPv4. Подключиться не получится.
   - Строка выглядит так:
     ```
     postgresql://postgres.<ref>:[YOUR-PASSWORD]@aws-0-<регион>.pooler.supabase.com:5432/postgres
     ```
3. Замените `[YOUR-PASSWORD]` (вместе со скобками) на пароль от базы.
   - Пароль забыт → **Project Settings → Database → Reset database password**.
     ⚠️ Если к этой базе подключаются другие ваши приложения, после сброса
     им тоже придётся сменить пароль.
   - Если в пароле есть символы `@ : / ? # [ ] %`, замените их кодами:
     `@` → `%40`, `:` → `%3A`, `/` → `%2F`, `?` → `%3F`, `#` → `%23`,
     `[` → `%5B`, `]` → `%5D`, `%` → `%25`. Иначе строка «сломается».
4. Больше в Supabase ничего делать не нужно. При первом запуске бот сам
   создаст схему `readit` и в ней таблицу `links`. Другие таблицы проекта
   он не трогает.

> 🔒 Схема `readit` не видна через публичный API Supabase: по умолчанию
> там открыта только схема `public`. Не добавляйте `readit` в «Exposed
> schemas» в настройках API. На таблице дополнительно включён RLS.

## Шаг 2. Добавьте переменную в Render

Render → ваш сервис → **Environment**:

| Переменная     | Что сделать                                                 |
|----------------|-------------------------------------------------------------|
| `BOT_TOKEN`    | уже есть — не трогайте                                      |
| `DATABASE_URL` | **добавьте**: строка из шага 1 с подставленным паролем      |
| `DB_PATH`      | если есть — удалите, больше не нужна                        |

Нажмите **Save Changes**. Render перезапустит сервис со старым кодом. Это
нормально: старый код новую переменную просто не заметит.

Адрес для webhook задавать **не нужно**: бот берёт его из переменной
`RENDER_EXTERNAL_URL`, которую Render заполняет сам
(`https://<сервис>.onrender.com`). `WEBHOOK_BASE_URL` нужна, только если
у бота свой домен.

## Шаг 3. Проверьте настройки сервиса

Render → сервис → **Settings**:

- **Build Command:** `pip install -r requirements.txt`
- **Start Command:** `python main.py`
- **Health Check Path** (необязательно): `/`
- Тип инстанса можно оставить **Free**.

## Шаг 4. Смёржите изменения и задеплойте

1. Смёржите в `main` сначала PR #1, затем PR с этими изменениями.
2. Если включён **Auto-Deploy**, Render пересоберёт бота сам. Если нет —
   **Manual Deploy → Deploy latest commit**.
3. Откройте **Logs**. После запуска там должны появиться строки:
   ```
   Режим webhook: https://<сервис>.onrender.com/webhook
   База данных: PostgreSQL, схема readit.
   Webhook установлен: https://<сервис>.onrender.com/webhook
   ```

Webhook в Telegram бот подключает сам — при каждом запуске. Вручную ничего
регистрировать не нужно.

## Шаг 5. Убедитесь, что всё работает

1. Откройте в браузере (вместо `<ТОКЕН>` — токен бота):
   ```
   https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo
   ```
   ⚠️ В этой ссылке ваш токен — не отправляйте её никому и не публикуйте скриншот.

   В ответе должно быть:
   - `"url": "https://<сервис>.onrender.com/webhook"`;
   - `"pending_update_count": 0` или небольшое число (сообщения в очереди);
   - нет поля `last_error_message`. Если оно есть, сверьте `last_error_date`:
     старая ошибка не страшна.
2. Напишите боту `/start`. Если сервис спал, Render его разбудит, и первый
   ответ придёт примерно через минуту. Следующие ответы приходят сразу.
3. Пришлите ссылку. В Supabase (**Table Editor** → схема `readit` →
   таблица `links`) появится новая строка.

## Шаг 6. Уберите «будильник», если он был

Если вы настраивали UptimeRobot, cron-job.org и т.п., чтобы бот не засыпал,
теперь это не нужно: бота будит сам Telegram. Если оставить пинг, бот будет
отвечать без минутной задержки после сна. Бесплатных 750 часов в месяц
хватает на один сервис, работающий круглосуточно.

## Если что-то пошло не так

| Что видно в логах Render или в `getWebhookInfo` | Что делать |
|---|---|
| `❌ DATABASE_URL должен начинаться с postgresql://` | Вставлен адрес проекта `https://….supabase.co`. Нужна строка подключения из шага 1 |
| `❌ В DATABASE_URL остался шаблон [YOUR-PASSWORD]` | Подставьте пароль от базы |
| `password authentication failed` | Неверный пароль или спецсимволы в нём не заменены кодами (шаг 1.3) |
| `Network is unreachable` или таймаут подключения к базе | Скорее всего, взята Direct connection — нужен **Session pooler** |
| `last_error_message: Wrong response from the webhook: 401 Unauthorized` | Бот не узнал секрет запроса. Перезапустите сервис (**Manual Deploy**) — бот заново подключит webhook с правильным секретом |
| Бот перестал отвечать, в логах ошибки подключения к базе | Бесплатный проект Supabase ставится на паузу после 7 дней без активности. Откройте дашборд Supabase и нажмите **Restore** |

**Откат на старую версию.** Render → **Events** → нажмите **Rollback**
у прошлого деплоя. Затем удалите webhook, открыв
`https://api.telegram.org/bot<ТОКЕН>/deleteWebhook`. Иначе старая версия
(polling) получит от Telegram ошибку `Conflict`.

**Старые ссылки.** Из SQLite на Render в Supabase ничего не переносится.
Бесплатный диск Render стирался при каждом деплое и сне, так что там почти
наверняка пусто.

## Локальный запуск после перехода на webhook

Не запускайте бота на компьютере с боевым токеном. У бота включён webhook,
поэтому локальный запуск откажется стартовать и объяснит почему. Так и
задумано: иначе он «увёл» бы бота с сервера. Для экспериментов заведите
отдельного тестового бота у [@BotFather](https://t.me/BotFather) и впишите
его токен в `.env`. Без `DATABASE_URL` локально используется SQLite-файл.
