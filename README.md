# 📚 Read It Later — Telegram-бот

Функциональный Telegram-бот «прочитай позже»: присылаете боту ссылку — он
сохраняет её вместе с заголовком статьи, чтобы вы могли вернуться к ней позже.

## 🆕 Что изменено и почему

Коротко: бот стал безопаснее, перестал «падать» на кривых ссылках и длинных
заголовках, а все команды теперь проверяются автотестами. Сами команды
(`/start`, `/list`, `/random`, кнопка «✅ Отметить прочитанным») работают
так же, как раньше.

### 1. Через бота больше нельзя «подсмотреть» внутренние страницы сервера

**Было:** бот открывал любую присланную ссылку — в том числе
`http://localhost/...`, `http://192.168.1.1/` или служебный адрес облака
`http://169.254.169.254/`. Любой человек мог прислать такую ссылку и получить
в ответ заголовок внутренней страницы сервера (это называется атака SSRF).

**Стало:** такие ссылки сохраняются как обычно, но без заголовка — бот их
не открывает. Проверяется каждый редирект и то, куда на самом деле указывает
домен (чтобы нельзя было обойти защиту «хитрым» DNS).

Заодно починена загрузка заголовков:

- ссылка вида `https://a..b` больше не ломает бота (раньше он молчал и ничего
  не сохранял);
- заголовок находится, даже если он не в самом начале страницы (раньше бот
  читал только первый кусок ответа и часто сохранял голый URL);
- у сайтов в кодировке windows-1251 больше нет «кракозябр» вместо заголовка;
- если тега `<title>` нет, берётся `og:title` (заголовок для превью);
- из одного сообщения сохраняется до 10 ссылок (защита от флуда), повторы
  убираются, заголовки грузятся одновременно, а не по очереди.

### 2. Исправлено зачёркивание и слишком длинные сообщения

- После нажатия «Отметить прочитанным» слова заголовка склеивались:
  «Hello World» превращалось в «H̶e̶l̶l̶o̶W̶o̶r̶l̶d̶». Теперь пробелы на месте.
- Очень длинная ссылка вместе с заголовком не влезала в лимит Telegram
  (4096 символов): `/list` и `/random` падали и не показывали остальные
  ссылки. Теперь заголовок обрезается до 300 символов, а сообщение — под лимит.

### 3. Порядок в репозитории

- Удалены `read_it_later.dbx` и `smoke_test.db` — это файлы базы данных,
  и в первом лежали реальный Telegram ID и сохранённая ссылка. Бот их
  не использует: база `read_it_later.db` создаётся сама при запуске.
  Из истории git они не вычищены — для этого пришлось бы перезаписать
  ветку `main`; репозиторий приватный, данных там мало.
- `.gitignore` теперь не пускает в git любые файлы баз и `.env.*`.
- Добавлен `.env.example` — README на него ссылался, а файла не было.
- В `requirements.txt` добавлены верхние границы версий, чтобы выход,
  например, aiogram 4 не сломал бота при очередном деплое.

### 4. Автотесты

72 теста проверяют бота без настоящего Telegram: все запросы бота к Telegram
API перехватывает подставная сессия, а вместо сайтов работает локальный
тестовый сервер. Тесты сами запускаются в GitHub Actions на каждый pull
request. Как запустить их вручную — в разделе «Установка и запуск».

### 🔐 Проверка токена

Токена бота нет ни в коде, ни в истории коммитов: проверены все версии всех
файлов за всю историю репозитория (поиск по формату токена и сканер
`detect-secrets`). Токен берётся только из переменной окружения `BOT_TOKEN`
(локально — из файла `.env`, который в git не попадает).

### Что ещё стоит сделать

- **Надёжное хранение ссылок** — см. раздел «Где бот сейчас работает»:
  на бесплатном хостинге база может стираться при каждом перезапуске.
- **Скрытые ссылки и подписи к фото.** Если переслать боту пост из канала,
  где ссылка «спрятана» в тексте («Читать далее»), или фото с подписью,
  бот сейчас молча их игнорирует.
- Мелочи: вернуть в `main.py` регистрацию меню команд (`set_my_commands`),
  не сохранять одну и ту же ссылку дважды, при желании — пускать в бота
  только свои Telegram ID.

## 🌍 Где бот сейчас работает

В репозитории нет файлов деплоя (`render.yaml`, `Procfile`, `Dockerfile`),
поэтому по коду место запуска точно не определить. Но есть сильная подсказка:
`main.py` поднимает HTTP-заглушку «Bot is live!» на порту из переменной `PORT`
(по умолчанию `10000`). Так запускают бота на **Render.com** как бесплатный
Web Service: Render требует, чтобы сервис слушал порт, и 10000 — его порт
по умолчанию. Проверьте в дашборде Render (или там, где вы деплоили).

Если это бесплатный тариф Render, учтите два ограничения:

- **Сервис засыпает** через 15 минут без входящих HTTP-запросов, и бот
  перестаёт отвечать (сообщения из Telegram его не будят). Обычно это
  обходят внешним «пингом» адреса сервиса раз в 5–10 минут (например,
  UptimeRobot) или переходят на платный тариф.
- **Диск временный**: файл базы SQLite стирается при каждом деплое и
  перезапуске, сохранённые ссылки пропадают. Для надёжного хранения нужна
  внешняя база (например, бесплатный PostgreSQL) или платный постоянный диск.

Если на Render включён автодеплой, после мержа изменений в `main` бот
пересоберётся сам. Типичные настройки: Build Command
`pip install -r requirements.txt`, Start Command `python main.py`,
переменная окружения `BOT_TOKEN`.

## ✨ Возможности

- 🔗 **Сохранение ссылок** — пришлите боту любую `http/https` ссылку (или до
  10 ссылок в одном сообщении), он асинхронно скачает начало страницы,
  вытащит заголовок и сохранит запись.
- 📚 **`/list`** — список из 5 последних непрочитанных ссылок, под каждой —
  inline-кнопка «✅ Отметить прочитанным».
- ✅ **Inline-кнопки** — при нажатии запись помечается прочитанной в БД,
  а сообщение редактируется: заголовок зачёркивается, кнопка исчезает.
- 🎲 **`/random`** — одна случайная непрочитанная ссылка, чтобы почитать прямо сейчас.
- 🛡️ **Устойчивость к ошибкам** — если сайт недоступен, ссылка «кривая» или
  заголовка нет, бот сохранит просто URL и не упадёт.
- 🔒 **Безопасность** — бот не открывает ссылки на localhost, локальную сеть
  и служебные адреса облака.

## 🚀 Установка и запуск

### Шаг 1. Получите токен бота

1. Откройте в Telegram [@BotFather](https://t.me/BotFather).
2. Отправьте команду `/newbot` и следуйте инструкциям.
3. Скопируйте выданный токен (вида `123456789:AAF...`).

### Шаг 2. Установите зависимости

```bash
# (рекомендуется) создать виртуальное окружение
python -m venv venv

# активировать окружение:
# Windows (PowerShell):
venv\Scripts\Activate.ps1
# Linux / macOS:
source venv/bin/activate

# установить зависимости
pip install -r requirements.txt
```

### Шаг 3. Настройте токен

Скопируйте шаблон `.env.example` в файл `.env` и вставьте свой токен:

```bash
# Windows (PowerShell)
Copy-Item .env.example .env

# Linux / macOS
cp .env.example .env
```

Содержимое `.env`:

```env
BOT_TOKEN=123456789:AAF...ваш_токен...
```

> ⚠️ Никогда не коммитьте файл `.env` в git — в нём хранится секретный токен.
> На хостинге (Render и т.п.) задайте `BOT_TOKEN` в настройках переменных
> окружения, а не в коде.

### Шаг 4. Запустите бота

```bash
python main.py
```

В консоли появится сообщение о запуске — бот готов к работе.
Остановить бота: `Ctrl+C`.

> ⚠️ Не запускайте бота локально с тем же токеном, пока он работает на сервере:
> Telegram отдаёт сообщения только одному процессу, второй получит ошибку
> `Conflict`. Для экспериментов заведите у @BotFather отдельного тестового бота.

### Шаг 5. Запустите тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Токен и интернет не нужны: запросы к Telegram подменены, каждый тест
работает со своей временной базой.

## 🗄️ Схема базы данных

Таблица `links` создаётся автоматически при первом запуске:

| Поле         | Тип     | Описание                                        |
|--------------|---------|-------------------------------------------------|
| `id`         | INTEGER | Первичный ключ (автоинкремент)                  |
| `user_id`    | INTEGER | Telegram ID пользователя                        |
| `url`        | TEXT    | Сохранённая ссылка                              |
| `title`      | TEXT    | Заголовок страницы (или URL при ошибке парсинга)|
| `is_read`    | INTEGER | Флаг прочтения: `0` — нет, `1` — да             |
| `created_at` | TEXT    | Дата сохранения (UTC, ISO-формат)               |

## 🧩 Как это работает

1. Пользователь присылает текст со ссылкой → роутер `links` находит все
   `http/https` URL регулярным выражением (до 10 за раз, без повторов).
2. Для каждой ссылки бот проверяет, что адрес публичный (не localhost и не
   локальная сеть), и `aiohttp` скачивает начало страницы — до `</title>`,
   но не больше 256 КБ. Каждый редирект проверяется так же.
   `BeautifulSoup` извлекает `<title>` (или `og:title`).
3. Запись сохраняется в SQLite через `aiosqlite` с `is_read=False`.
4. При нажатии кнопки «Отметить прочитанным» бот получает `callback_query`
   с данными `mark_read:<id>`, обновляет запись и редактирует сообщение
   (заголовок зачёркивается юникод-символом U+0336).
