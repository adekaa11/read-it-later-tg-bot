# 📚 Read It Later — Telegram-бот

Функциональный Telegram-бот «прочитай позже»: присылаете боту ссылку — он
сохраняет её вместе с заголовком статьи, чтобы вы могли вернуться к ней позже.

> 🚀 **Деплой на Render + Supabase с webhook — пошагово:** [DEPLOY.md](DEPLOY.md)

## 🆕 Что изменено и почему

Команды (`/start`, `/list`, `/random`, кнопка «✅ Отметить прочитанным»)
работают так же, как раньше. Изменения шли двумя обновлениями.

### Обновление 2: пересланные посты, Supabase, webhook

#### 5. Ссылки из пересланных постов и подписей к фото

**Было:** бот видел только ссылки, написанные прямо в тексте. Пересланный
пост из канала, где ссылка «спрятана» под словами («Читать далее»), и фото
с подписью он молча игнорировал. Ссылки со скобками (например, на Википедию)
обрезались на «(».

**Стало:** ссылки берутся из текста и из подписей к фото, видео и файлам —
в том числе скрытые под словами. Ссылки со скобками сохраняются целиком.

#### 6. Ссылки хранятся в Supabase

**Было:** база лежала в файле SQLite на диске Render. Бесплатный диск
временный: при каждом деплое и после каждого «сна» сервиса сохранённые
ссылки пропадали.

**Стало:** на сервере ссылки хранятся в PostgreSQL вашего проекта Supabase,
в отдельной схеме `readit`. Схема создаётся сама и не мешает остальным
таблицам проекта. Строка подключения берётся из переменной окружения
`DATABASE_URL`. Без неё (локальный запуск, тесты) бот, как и раньше,
работает с файлом SQLite.

#### 7. Webhook: Telegram сам будит бота

**Было:** бот сам опрашивал Telegram (polling). Бесплатный Render усыпляет
сервис через 15 минут без входящих запросов, и бот замолкал, пока кто-нибудь
не откроет его адрес в браузере.

**Стало:** на Render бот работает через webhook. Telegram присылает каждое
сообщение на адрес бота, и этот запрос будит сервис. Первый ответ после сна
приходит примерно через минуту, следующие — сразу. Сообщения не теряются,
повторная доставка одного и того же сообщения не создаёт дублей. Запросы
не от Telegram отклоняются: их выдаёт отсутствие секретного заголовка.
Локально бот по-прежнему работает через polling.

### Обновление 1: безопасность, исправления, тесты

#### 1. Через бота больше нельзя «подсмотреть» внутренние страницы сервера

**Было:** бот открывал любую присланную ссылку — в том числе
`http://localhost/...`, `http://192.168.1.1/` или служебный адрес облака
`http://169.254.169.254/`. Любой человек мог прислать такую ссылку и получить
в ответ заголовок внутренней страницы сервера (это называется атака SSRF).

**Стало:** такие ссылки сохраняются как обычно, но без заголовка — бот их
не открывает. Проверяется каждый редирект и то, куда на самом деле указывает
домен (чтобы нельзя было обойти защиту «хитрым» DNS).

Заодно починена загрузка заголовков:

- ссылка вида `https://a..b` больше не ломает бота (раньше он молчал и ничего
  не сохранял);
- заголовок находится, даже если он не в самом начале страницы (раньше бот
  читал только первый кусок ответа и часто сохранял голый URL);
- у сайтов в кодировке windows-1251 больше нет «кракозябр» вместо заголовка;
- если тега `<title>` нет, берётся `og:title` (заголовок для превью);
- из одного сообщения сохраняется до 10 ссылок (защита от флуда), повторы
  убираются, заголовки грузятся одновременно, а не по очереди.

#### 2. Исправлено зачёркивание и слишком длинные сообщения

- После нажатия «Отметить прочитанным» слова заголовка склеивались:
  «Hello World» превращалось в «H̶e̶l̶l̶o̶W̶o̶r̶l̶d̶». Теперь пробелы на месте.
- Очень длинная ссылка вместе с заголовком не влезала в лимит Telegram
  (4096 символов): `/list` и `/random` падали и не показывали остальные
  ссылки. Теперь заголовок обрезается до 300 символов, а сообщение — под лимит.

#### 3. Порядок в репозитории

- Удалены `read_it_later.dbx` и `smoke_test.db` — это файлы базы данных,
  и в первом лежали реальный Telegram ID и сохранённая ссылка. Бот их
  не использует: база `read_it_later.db` создаётся сама при запуске.
  Из истории git они не вычищены — для этого пришлось бы перезаписать
  ветку `main`; репозиторий приватный, данных там мало.
- `.gitignore` теперь не пускает в git любые файлы баз и `.env.*`.
- Добавлен `.env.example` — README на него ссылался, а файла не было.
- В `requirements.txt` добавлены верхние границы версий, чтобы выход,
  например, aiogram 4 не сломал бота при очередном деплое.

#### 4. Автотесты

Тесты проверяют бота без настоящего Telegram: все запросы бота к Telegram
API перехватывает подставная сессия, а вместо сайтов работает локальный
тестовый сервер. Тесты сами запускаются в GitHub Actions на каждый pull
request. Как запустить их вручную — в разделе «Локальный запуск».

#### 🔐 Проверка токена

Токена бота нет ни в коде, ни в истории коммитов: проверены все версии всех
файлов за всю историю репозитория (поиск по формату токена и сканер
`detect-secrets`). Токен берётся только из переменной окружения `BOT_TOKEN`
(локально — из файла `.env`, который в git не попадает).

### Что ещё стоит сделать

- Вернуть в `main.py` регистрацию меню команд (`set_my_commands`), чтобы
  `/list` и `/random` были в кнопке «Меню» Telegram.
- Не сохранять одну и ту же ссылку дважды.
- При желании пускать в бота только свои Telegram ID.

## 🌍 Где бот работает

- **Бот** — на [Render.com](https://render.com), бесплатный Web Service, режим
  webhook. Адрес сервиса бот узнаёт сам из переменной `RENDER_EXTERNAL_URL`.
- **Данные** — в Supabase (PostgreSQL), схема `readit` в существующем проекте.

Что настроить в Render и Supabase — пошагово в [DEPLOY.md](DEPLOY.md).

## ✨ Возможности

- 🔗 **Сохранение ссылок** — пришлите боту `http/https` ссылку или перешлите
  пост из канала (до 10 ссылок за раз). Бот найдёт ссылки в тексте и в подписи
  к фото, включая «скрытые» под словами, скачает начало страницы, вытащит
  заголовок и сохранит запись.
- 📚 **`/list`** — список из 5 последних непрочитанных ссылок, под каждой —
  inline-кнопка «✅ Отметить прочитанным».
- ✅ **Inline-кнопки** — при нажатии запись помечается прочитанной в БД,
  а сообщение редактируется: заголовок зачёркивается, кнопка исчезает.
- 🎲 **`/random`** — одна случайная непрочитанная ссылка, чтобы почитать прямо сейчас.
- 🛡️ **Устойчивость к ошибкам** — если сайт недоступен, ссылка «кривая» или
  заголовка нет, бот сохранит просто URL и не упадёт.
- 🔒 **Безопасность** — бот не открывает ссылки на localhost, локальную сеть
  и служебные адреса облака; webhook принимает запросы только от Telegram.

## 💻 Локальный запуск

Локально бот работает в режиме polling и хранит ссылки в файле SQLite —
ни Render, ни Supabase для этого не нужны.

> ⚠️ Для локального запуска заведите у @BotFather **отдельного тестового
> бота**. С боевым токеном бот не запустится: у него включён webhook, и
> локальный запуск «увёл» бы бота с сервера.

### Шаг 1. Получите токен тестового бота

1. Откройте в Telegram [@BotFather](https://t.me/BotFather).
2. Отправьте команду `/newbot` и следуйте инструкциям.
3. Скопируйте выданный токен (вида `123456789:AAF...`).

### Шаг 2. Установите зависимости

```bash
# (рекомендуется) создать виртуальное окружение
python -m venv venv

# активировать окружение:
# Windows (PowerShell):
venv\Scripts\Activate.ps1
# Linux / macOS:
source venv/bin/activate

# установить зависимости
pip install -r requirements.txt
```

### Шаг 3. Настройте токен

Скопируйте шаблон `.env.example` в файл `.env` и вставьте свой токен:

```bash
# Windows (PowerShell)
Copy-Item .env.example .env

# Linux / macOS
cp .env.example .env
```

Содержимое `.env`:

```env
BOT_TOKEN=123456789:AAF...ваш_токен...
```

> ⚠️ Никогда не коммитьте файл `.env` в git — в нём хранится секретный токен.
> На хостинге задайте `BOT_TOKEN` и `DATABASE_URL` в настройках переменных
> окружения, а не в коде.

### Шаг 4. Запустите бота

```bash
python main.py
```

В консоли появится «Бот запущен в режиме polling» — бот готов к работе.
Остановить бота: `Ctrl+C`.

### Шаг 5. Запустите тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Токен и интернет не нужны: запросы к Telegram подменены, каждый тест работает
со своей временной базой SQLite. Чтобы прогнать те же тесты на PostgreSQL,
задайте `TEST_DATABASE_URL` (каждый тест создаёт и удаляет свою временную
схему; так тесты идут в CI):

```bash
TEST_DATABASE_URL=postgresql://postgres:postgres@localhost:5432/postgres pytest
```

## 🗄️ Схема базы данных

Таблица `links` создаётся автоматически при первом запуске. В PostgreSQL она
лежит в схеме `readit` (`readit.links`), в SQLite — в файле `DB_PATH`.

| Поле         | PostgreSQL    | SQLite  | Описание                                        |
|--------------|---------------|---------|-------------------------------------------------|
| `id`         | `BIGINT`      | INTEGER | Первичный ключ (автоинкремент)                  |
| `user_id`    | `BIGINT`      | INTEGER | Telegram ID пользователя                        |
| `url`        | `TEXT`        | TEXT    | Сохранённая ссылка                              |
| `title`      | `TEXT`        | TEXT    | Заголовок страницы (или URL при ошибке парсинга)|
| `is_read`    | `BOOLEAN`     | INTEGER | Флаг прочтения                                  |
| `created_at` | `TIMESTAMPTZ` | TEXT    | Дата сохранения (UTC)                           |

## 🧩 Как это работает

1. На Render Telegram присылает каждое сообщение на `https://<сервис>.onrender.com/webhook`
   (с секретным заголовком). Локально бот сам забирает сообщения (polling).
2. Роутер `links` ищет ссылки в тексте или подписи: и видимые, и «скрытые»
   под словами (разметка Telegram), плюс регулярное выражение как запасной
   вариант. До 10 ссылок за раз, без повторов.
3. Для каждой ссылки бот проверяет, что адрес публичный (не localhost и не
   локальная сеть), и `aiohttp` скачивает начало страницы — до `</title>`,
   но не больше 256 КБ. Каждый редирект проверяется так же.
   `BeautifulSoup` извлекает `<title>` (или `og:title`).
4. Запись сохраняется в базу (`is_read = false`): в Supabase, если задан
   `DATABASE_URL`, иначе в SQLite.
5. При нажатии кнопки «Отметить прочитанным» бот получает `callback_query`
   с данными `mark_read:<id>`, обновляет запись и редактирует сообщение
   (заголовок зачёркивается юникод-символом U+0336).
